# Project112 — сценарий разработки

## 1. Текущая цель

Создать демонстрационный видеотестер для Pentagon 1024 в UnrealSpeccy. Переключение режимов выполняется клавишей **Space**. На каждом шаге экран очищается и выводится таблица ASCII 32–127 для визуальной оценки заполнения экрана и читаемости.

Репозиторий: https://github.com/JTCyborg/Project112  
Рабочая ветка: `main`  
Основной исходник: `112/src/main.asm`  
Сборка Windows: из каталога `112` выполнить `build.bat` (sjasmplus).

## 2. Демонстрационные режимы

Текущая последовательность записи в порт `#EFF7`:

| № | Значение | Назначение |
|---:|---:|---|
| 1 | `$00` | Стандартный Spectrum 256×192 |
| 2 | `$02` | 512×192 |
| 3 | `$20` | Аппаратный мультиколор / A4B |
| 4 | `$01` | 16 цветов |
| 5 | `$40` | Pentagon 384×304 |

Для целевого UnrealSpeccy используется актуальная карта режима: D0 — 16-color, D1 — 512×192, D5 — hardware multicolor, D6 — 384×304. Не использовать исторические назначения битов из старых публикаций без сверки с эмулятором.

## 4. Аппаратная карта и источники

- `Video/bd10p1mb (3).txt` — историческая статья Pentagon 1024. Использовать как исторический источник; назначения битов могли измениться.
- `Video/an32m384 (1).htm` — схема и поля 384×304.
- `Video/ig7m384p (1).htm` — процедуры и адресация 384×304.
- `Video/ec05byte (1).txt` — отдельная реализация двойного разрешения Byte 01, не спецификация Pentagon.

Для проверки именно в UnrealSpeccy фиксировать версию эмулятора и параметры Pentagon 1024 (включая `EFF7mask=0`). Не считать режим проверенным только по факту успешной записи в порт.

### Разработка реального теста ширины строки (2026-11-02)

Требование: при переключении #EFF7 на экране должна меняться фактическая ширина тестовой строки, а не только подпись режима.

Уточнённая адресация по документации проекта и Pentagon:

- [ ] STANDARD 256x192: 32 байта/знакоместа в строке, стандартная bitmap-развёртка.
- [ ] 512x192: 64 монохромных байта в строке; чётные байты находятся в DFILE $4000-$57FF, нечётные — в $6000-$77FF. Требуется чередование адресов при выводе.
- [ ] HARDWARE MULTICOLOR: 32 байта пиксельной строки; атрибуты берутся из второго DFILE ($6000-$77FF).
- [ ] 16col: 32 знакоместа; один байт кодирует два цветных пикселя, четыре экранные области первого экрана: $C000, $4000, $E000, $6000. Требуется формирование четырёх цветовых байтов на каждую строку знакоместа.
- [ ] PENTAGON 384x304: 48 байтов в строке; адресация только через канонические YSC384/XYSC384/SA384, боковые поля в RAM 1, центральное поле в RAM 5.
